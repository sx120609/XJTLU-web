# 靠浦代码审计与缺陷修复记录（2026-07-19）

## 审计边界

本轮在阶段 0—5 成果之上继续增量审计，没有推倒现有架构，也没有改动登录页面、认证 Store、记住密码逻辑或品牌资产。检查范围包括：

- 根项目脚本与三套 npm 依赖树；
- Express 路由、中间件、Prisma Schema、10 段迁移与后台任务；
- Vue 路由、API 契约、市集、求购、学习资料、合作商户、推广和后台页面；
- Android、Flutter、HarmonyOS 的入口配置与兼容路由；
- 现有 0—5 阶段报告、自动化测试、真实 PostgreSQL 集成测试和生产构建。

## 已确认并修复的问题

1. **非法分页参数导致 500**：`page=abc`、`size=Infinity` 会把 `NaN` 传给 Prisma。现已统一使用有默认值、整数化和上下界的查询参数解析，并覆盖公开路由、管理路由和后台服务。
2. **非法数字 ID 导致 500**：核心公开详情路由会在进入数据库前拒绝非法 ID；全局错误处理中补充了 Prisma 参数、缺失记录和数据冲突的安全映射，不再把常见请求错误伪装成服务器故障。
3. **收藏并发与计数漂移**：商品和商户收藏改为 PostgreSQL 事务级互斥，计数从真实收藏记录重算；快速双击、多个标签页或多个应用节点不会再产生唯一键 500 或负计数。
4. **自刷业务指标**：后端拒绝收藏自己发布的商品、收藏自己的商户主页和咨询自己的商户主页，不再只依赖前端按钮禁用。
5. **重复咨询展示错误**：商户咨询按“商户 + 用户 + 自然日”去重；接口返回本次是否计数和数据库真实咨询数，前端不再无条件 `+1`。
6. **推广并发状态竞争**：同一用户重复提交相同待确认推广、两名管理员同时确认同一订单、确认/驳回/取消相互竞争时均由事务锁串行处理，只允许一次合法状态迁移。
7. **推广统计可被伪造转发头绕过去重**：访客标识改用 Express 按可信代理配置解析后的 `req.ip`，不再直接信任客户端提交的 `X-Forwarded-For`。
8. **失效订单仍可能形成推广标签**：标签序列化、首页推广、合作商户列表、全局搜索和用户主页现在同时核对订单状态、开始时间和到期时间。
9. **商户响应包含内部关系字段**：公开商户对象不再展开内部收藏记录和活动订单关系，只保留明确的推广标签数据。
10. **推广空价格会被解释为 0 元**：空字符串现在返回参数错误；显式数字 0 仍可由管理员按业务需要配置。
11. **Excel 空表头导致列错位**：成绩表中间存在空表头时，原逻辑会压缩列名但继续按压缩后的下标取值。现按原始列下标映射，姓名、课程、成绩等字段不会错列。
12. **Excel 输入缺少资源与原型键边界**：增加 5 MB、5000 行、100 字段限制，拒绝 `__proto__`、`prototype`、`constructor` 字段，并使用无原型对象承载行数据。
13. **生产依赖漏洞**：升级 Multer、Morgan、Undici、DOMPurify、form-data、ECharts 和 vue-echarts；移除代码中完全未使用的 `NeteaseCloudMusicApi` 及其易受攻击的传递依赖。

## 当前验证结果

- 服务端 TypeScript 类型检查通过；
- 前端 Vue TypeScript 检查与 Vite 生产构建通过；
- 非法分页与非法详情 ID 真实 HTTP 用例通过；
- 商品/商户双并发收藏、推广双申请、推广双确认、重复咨询和伪造转发头去重的真实 PostgreSQL 用例通过；
- Prisma Schema 有效，10 段迁移状态一致；隔离空库迁移可生成 91 张表并自动清理；
- 服务端生产依赖 `npm audit --omit=dev` 为 0；
- 前端只剩 `xlsx@0.18.5` 的 1 个高风险依赖项，npm 当前无可用修复版本。本轮已加输入边界，但替换解析库仍是阶段 6 的发布门槛。

## 保留项与边界

- 登录体验按用户明确要求保持原样，本轮没有修改登录相关文件。
- 学生商品继续采用购买意向、预约、校内面交和双方确认；平台不经手商品款、不抽佣。
- 推广订单继续人工核验，不与 EasyPay、赞助或学生商品支付混用。
- 旧 CPU 教务、工具和多端兼容代码仍有保留。没有依据真实使用数据前不批量删除，阶段 6 先做调用与流量清单。
- 本轮未新增数据库字段或迁移，避免为修复已有逻辑引入不必要的数据变更。
