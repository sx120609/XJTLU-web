# 靠浦下一轮五阶段规划（阶段 6—10，待业务答案校准）

## 规划原则

下一轮不扩张成“什么都有”的校园门户。所有工作围绕现有四条产品主线：可信交易、求购匹配、免费原创学习内容、明确标注的合作商户与推广。每阶段必须先有指标基线、后有自动化与真实流程验收；未通过发布门槛不进入下一阶段。

## 阶段 6：发布稳定化与安全收口

目标：把阶段 0—5 从“功能完整”提升到“可持续上线和排障”。

- 替换无安全修复版本的 `xlsx` 解析依赖，保留现有成绩表导入/模板体验；
- 将剩余数字路由参数、分页、状态枚举和金额输入统一到共享校验层；
- 为交易、求购、推广、审核等写操作补齐幂等键或事务冲突策略；
- 增加请求 ID、结构化错误日志、定时任务最近成功时间和后台健康面板；
- 固化数据库备份、恢复演练、迁移预演和依赖审计为发布命令；
- 清点旧 CPU 路由、外部地址、原生壳入口和实际调用量，只归档已确认无人使用的部分。

验收门槛：生产依赖无高危/严重项；全量测试、空库迁移、备份恢复、核心 HTTP 冒烟全部通过；任一失败可定位到请求和任务。

## 阶段 7：供给与发布转化

目标：先解决“有没有足够真实内容”，不急于加推荐算法。

- 基于现有统一发布中心优化商品、求购和免费原创的表单层级、草稿恢复、图片压缩/排序和规则即时提示；
- 复用现有分享组件，完善发布完成后的分享卡片、复制文案和站内关联讨论入口；
- 为首次发布、空列表和低质量草稿提供清晰引导，不制造演示数据；
- 在后台增加发布漏斗、审核原因和品类缺口视图；
- 针对移动 Web 与现有原生壳做相同信息架构的触控验收。

验收门槛：发布完成率、有效上架率和审核退回后二次提交率有基线且改善；不能以增加必填项换取表面完整度。

## 阶段 8：匹配与履约闭环

目标：让现有商品与求购真正相遇，并降低预约后的失联和爽约。

- 建立可解释的规则匹配：品类、关键词、校区、预算和成色，不上黑箱推荐；
- 为用户提供可关闭的求购响应、相似商品和预约到期提醒；
- 完善接受意向后的联系方式、约见确认、改期、取消和爽约证据链；
- 在“我的交易”合并展示待处理动作和时间窗口，减少跨标签寻找；
- 对通知去重、频率、隐私与撤回做专项测试。

验收门槛：从商品/求购浏览到意向、从意向到预约、从预约到双方完成的漏斗可量化；提醒不得泄露接受前联系方式。

## 阶段 9：运营与信任增长

目标：给小规模运营团队可执行的工具，而不是堆报表。

- 建立交易、求购、免费原创、商户和推广五条运营漏斗；
- 将举报、违规、申诉、审核和信用变化串成同一审计视图；
- 用配置化专题承接开学季、毕业季、教材季等场景，复用现有内容与排序能力；
- 展示推广曝光、点击、咨询和后续意向的隐私最小化归因；
- 增加商户资料复核、主页到期和投诉集中提醒。

验收门槛：运营人员能在固定时限内处理积压；所有人工动作有理由、操作者和时间记录；专题关闭后不残留硬编码入口。

## 阶段 10：可持续商业化与规模验证

目标：在不碰学生商品款的前提下，验证推广服务是否值得继续投入。

- 根据前四阶段真实数据决定继续人工核验，还是只为推广订单接入独立支付；
- 完善推广排期冲突、库存上限、续期、退款/补偿和发票记录，不改变学生交易边界；
- 为商户建立周期复核、服务下架、续费提醒和历史效果快照；
- 做数据库索引、缓存命中、列表 P95、上传内存、可访问性和移动端性能专项；
- 形成灰度发布、回滚、数据核对和版本复盘模板。

验收门槛：商业展示全部明确标注；推广收入、人工成本、投诉率和转化率能共同评估；未达到阈值时允许关闭商业位而不影响交易、求购和学习主线。

## 当前建议的阶段顺序

阶段 6 是硬门槛。阶段 7—10 的顺序基于当前开发库商品、订单和学习资料数据接近空白这一事实，属于待真实运营数据校准的假设；如果线上已有稳定供给，应把阶段 8 的匹配履约提前，而不是重复做发布入口。
