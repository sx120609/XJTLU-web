# 迭代三：靠浦 V1 信任、分发与上线收口

## 1. 迭代定位

迭代三是靠浦 V1 的收口版本，不再扩张新的业务主线。产品目标是把已经完成的校园实物交易、付费学习资料交易、课表、融合门户和校园广场，通过统一信誉、交易积分、热门排序、增长指标和上线准备度连接为一个能够运营的校园交易产品。

规划书中的优先级结论如下：

- P0 交易闭环、资料交付、治理、安全、备份与恢复已经由前序阶段和迭代一、二实现；
- P1 中个性化课表、通知、个人主页和基础运营统计已经存在；
- P1 中仍缺少完整闭环的是交易积分，以及覆盖商品、求购、资料、帖子且具有时间衰减和抗刷约束的热门排序；
- 信誉目前分散为论坛信誉、实物市集信用和资料创作者质量，本迭代必须统一“对外解释”，但不能粗暴合并含义不同的分值；
- V1 上线标准不仅是代码可构建，还必须能明确展示供给、运营队列、增长指标和技术门禁是否达标。

## 2. 产品原则

### 2.1 不制造虚假繁荣

- 热门排序只使用真实浏览、收藏、响应、订单、评价、退款、申诉和治理记录；
- 运营数据只统计真实数据库记录；
- 平台供给不足时，上线准备度必须明确显示未达标，不使用演示数字掩盖；
- 交易积分不兑换现金，不影响资金结算，不形成充值或提现能力。

### 2.2 信誉与积分分工

- 交易信誉回答“这个用户是否可靠”；
- 交易积分回答“这个用户为靠浦交易生态贡献了多少”；
- 论坛信誉继续用于论坛准入和匿名额度，不伪装为交易信用；
- 资料创作者质量继续反映资料业务质量，并作为统一交易信誉的客观组成；
- 新用户在没有交易历史时显示“新用户，记录形成中”，而不是默认展示为低信誉。

### 2.3 热门排序可解释

热门排序必须满足：

- 时间自然衰减；
- 完成交易、有效响应和高质量评价权重大于单纯浏览；
- 浏览、收藏等易刷信号采用对数或封顶处理；
- 有效举报、退款、申诉和违规会降低曝光；
- 置顶或加急仍然明确标注，不混同自然热门；
- 前端能够展示主要入选原因，不输出无法解释的黑盒分数。

## 3. 交易积分规则

V1 使用不可变积分流水和用户余额缓存。相同业务事件只能记账一次，申诉通过或处理撤销时写入补偿流水，不改写历史流水。

| 业务事件 | 角色 | 积分 |
| --- | --- | ---: |
| 完成实物交易 | 买家、卖家 | +20 |
| 完成资料订单 | 买家 | +10 |
| 完成资料订单 | 创作者 | +20 |
| 求购响应被接受 | 响应者 | +8 |
| 发布真实交易评价 | 评价者 | +2 |
| 获得 4—5 星实物评价 | 被评价者 | +5 |
| 发布已购资料评价 | 买家 | +2 |
| 获得已购资料好评 | 创作者 | +5 |
| 资料版本审核通过 | 创作者 | +15 |
| 有效举报被确认 | 举报者 | +5 |
| 主动取消已接受的交易 | 取消者 | -5 |
| 市集或资料违规 | 被处理者 | -10 / -25 / -50 |
| 违规撤销或申诉通过 | 被处理者 | 恢复原扣分 |

积分余额最低为 0。等级只用于展示，不授予绕过审核、提高权限或资金权益：

- 0—49：校园新伙伴；
- 50—149：交易参与者；
- 150—349：可信贡献者；
- 350—699：校园协作者；
- 700 及以上：靠浦先锋。

## 4. 统一交易信誉

统一交易信誉保留现有 0—100 分结构，并扩展为：

- 校园身份；
- 实物与资料完成订单总数；
- 实物评价和已购资料评价；
- 爽约与主动取消；
- 有效举报、退款和争议；
- 市集违规与资料创作者违规；
- 资料创作者确认速度和质量等级；
- 交易积分等级。

对外公开最小必要的聚合结果。只有本人和运营人员可以查看具体限制、申诉和积分流水。

## 5. V1 热门排序

### 5.1 实物商品

信号包括浏览、收藏、购买意向、交易沟通、完成订单、卖家信誉、发布时间、有效举报和违规记录。

### 5.2 求购

信号包括有效响应、匹配订单、紧迫程度、发布时间、发布者信誉、举报和治理记录。

### 5.3 学习资料

信号包括样张预览、收藏、创建订单、完成订单、已购评分、退款、申诉、创作者质量和版本更新时间。

### 5.4 校园帖子

信号包括阅读、点赞、回复、最后回复时间、内容审核状态和发布时间。隐藏、审核拦截或违规内容不进入热门列表。

热门分数保存为可重建快照，不是不可变业务事实。后台任务周期刷新，热门接口在快照过旧时执行去重刷新。排序失败时回退到最新内容，不阻塞核心交易。

## 6. 增长指标

新增按用户、日期、产品入口去重的活动记录：

- 个性化课表；
- 融合门户；
- 校园广场；
- 实物市集；
- 学习资料。

只记录产品入口、来源入口和访问次数，不记录页面内容、学校密码、学号、搜索关键词或原始 IP。

运营后台展示：

- 新增校园认证用户；
- DAU、WAU；
- 七日回访率；
- 各入口活跃用户；
- 从课表、门户、广场进入交易模块的用户数；
- 商品、求购、资料、交易和售后核心指标。

## 7. 上线准备度

后台根据真实数据生成三类检查：

1. 产品供给：
   - 真实在售实物商品；
   - 有效求购；
   - 审核通过的付费资料；
   - 活跃资料创作者；
   - 校园广场内容；
   - 融合门户基础入口。
2. 运营能力：
   - 创作者与资料审核是否积压；
   - 商品、资料和帖子举报是否积压；
   - 资料售后首响是否超时；
   - 是否存在失败的关键后台任务。
3. 技术门禁：
   - 数据库迁移、类型检查、测试、构建、安全审计、包体预算和备份恢复演练由发布命令验证；
   - 后台只展示运行时能够真实判断的状态，不伪造部署环境结果。

准备度的阈值是运营建议，不是通过代码自动生成虚假供给的理由。

## 8. 全栈实施顺序

1. 数据迁移：积分流水、入口活动、热门快照字段和索引；
2. 领域服务：积分幂等记账、统一信誉聚合、热门公式、活动记录与上线准备度；
3. 业务接入：实物完成、求购响应、评价、资料审核、资料完成、举报、违规和申诉；
4. 查询与分发：商品、求购、资料、帖子和首页热门排序；
5. 前端：交易信用页、热门理由、自动入口记录和运营看板；
6. 运维：热门刷新后台任务、数据库检查、历史数据回填和发布文档；
7. 验证：公式单测、契约测试、并发幂等测试、真实 PostgreSQL 集成、双端类型检查、构建、依赖审计和包体预算。

## 9. 验收标准

- [x] 相同交易或治理事件重复执行不会重复计分；
- [x] 扣分不会让余额小于 0，撤销处理使用补偿流水；
- [x] 实物和资料交易都进入统一信誉记录；
- [x] 新用户不会被标记为低信誉；
- [x] 四类内容热门排序都有时间衰减、质量信号和治理降权；
- [x] 热门排序结果可解释，推广内容仍明确标识；
- [x] 入口活动不记录敏感信息，重复访问按日聚合；
- [x] 运营后台展示真实核心指标和 V1 准备度；
- [x] 后台任务失败不阻断最新内容和交易主链；
- [ ] 全量单测、集成测试、类型检查、生产构建、迁移和安全检查通过。
